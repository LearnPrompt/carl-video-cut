# 逐秒自检

`check_frames.sh` 每秒抽一帧并烧录秒数，每 12 帧拼成一张 4x3 联系表。逐张 Read，按下面清单看每一格，问题写进问题表。本机 ffmpeg 没编 drawtext，脚本会自动改用 Pillow 烧秒数；两者都没有时以文件名 `sec_NNN` 为准。抽帧用 select 精确落在整秒；`fps=1` 会取到每秒后约 0.47 秒的帧，标签和画面错位，别换回去。

场与场之间的淡出淡入会在切点留下不到 0.2 秒的纯底色帧，属于设计的转场，切点正好落在整秒时联系表会看到空白格，不算问题。打字、滚数这类效果在整秒抽帧里只能看到片段，额外用 `ffmpeg -ss <秒> -frames:v 1` 抽几个中间时刻核对。

## 逐秒清单

- **文字**：溢出画布或容器、被截断、换行把一个词拆开、与背景对比不足、中文标点落在行首、字号小到手机上看不清（1080p 画面里正文低于 36px 就算小）。
- **数字**：与 ledger 不一致、滚动停在错误的终值、单位丢失、小数位前后不统一。
- **截图**：被拉伸变形、模糊、聚光框没对准目标、露出隐私信息（二维码、邮箱、token 要模糊）。
- **时序**：空白帧或纯底色帧（片头片尾以外）、两幕之间闪一下、元素该出现时还没出现、同一秒内所有元素一起淡入。
- **构图**：元素贴边（四周留白少于 80px）、多个元素重叠遮挡、视线没有焦点。
- **一致性**：同类元素位置在幕与幕之间跳动、强调色用了第二种。

问题表格式：

```
| 秒 | 问题 | 改法 | config 键 |
|---|---|---|---|
| 7 | 新柱数字 1.1 被柱顶遮住 | 数字上移 24px | scenes[2].layout.labelOffset |
```

改法能落在 config 键上的落在键上；只能改代码的，在改法里写清改了哪个函数，改完确认没有引入写死的值。

## 挑剔导演六项打分

问题表清空后，把自己当成挑剔的导演，对终版前的草稿逐项打 1 到 10 分，写一句扣分理由：

1. 信息清晰：静音看一遍，能不能复述出这支片要说的事。
2. 素材可信：每个文字、数字、截图都来自项目，示意画面有标注。
3. 节奏：每 2 到 4 秒有变化，没有拖沓或来不及读的幕。
4. 层级：每一帧只有一个视觉焦点。
5. 风格统一：符合 style.md，单强调色，没有默认 AI 味。
6. 完成度：首尾帧干净，最后一帧能直接当封面。

任何一项低于 8 分，挑最差的 3 个问题写明秒数改掉，再重新打分。

## 自动质检门

每支片交付前都要过，结果原样贴进交付说明，不改写成「已通过」三个字。

**确定性**（每一帧只由 t 决定）：

```bash
node ~/.claude/skills/carl-video-cut/scripts/check_determinism.mjs --dir <工程> [--transparent]
```

两次全新加载页面，一次按顺序直接 seek，一次打乱顺序且每个时刻前先跳到别处再回来，逐像素比。能抓到没带种子的随机数、Date.now、CSS 动画、计时器、依赖上一帧的累加。结果分三档：逐像素一致；栅格噪声（最大差不超过 2 个色阶，是 Chrome 按历史复用字形栅格造成的文字抗锯齿微差，和页面内容无关，算通过但要单列）；真不同（失败，差异图在 `_determinism/`）。`--strict` 时任何差异都算失败。口播片型只对动效叠层工程跑，不对真人底片跑。

检查本身跑不起来时（找不到 Chrome、10 秒内没给出调试地址、Chrome 中途退出、单条调用超过 60 秒）打印 `DETERMINISM ERROR` 并以退出码 2 结束，不会挂住，也不算通过。这时先看报错里 Chrome 最后几行输出。Chrome 不在默认位置时设 `CVC_CHROME`。在别的沙箱里跑（比如 Agent 框架的 seatbelt），Chrome 自带沙箱可能起不来，输出里会有 `sandbox initialization failed`；确认外层已经隔离、打开的是自己的工程后，再显式设 `CVC_CHROME_FLAGS=--no-sandbox`。这个开关会关掉 Chrome 自己的沙箱，默认不加，别的场合不要用。页面很重、加载超过一分钟时，用 `CVC_CDP_TIMEOUT=<秒>` 放宽单条调用时限。

**响度**：有音轨的片子，BGM 和音效分轨交给 `mix_audio.py` 混（BGM 按人声侧链让路），再两遍 loudnorm，口径统一 I -14 LUFS、真峰值不超过 -1.2 dBTP，在 AAC 编码之前做。`export_1080p.sh` 遇到有音轨的输入会自动做这一步，AAC 编码后实测真峰值，上冲超标就收紧目标重做。验收以 probe 的 ebur128 实测值为准。

**卡拍回测**（只对配乐驱动切点的片型；口播片型只回测落在 BGM 重音上的叠层动作）：

```bash
python3 ~/.claude/skills/carl-video-cut/scripts/beat_check.py --video final.mp4 --music bgm.wav [--cuts 1.5,3] [--half] --out beat_check.png
```

从成片音轨重新抽拍、定到真实起音、拟合成等间隔网格（BPM 只当参考），和原曲的网格比出配乐在成片里的整体偏移；切点缺省从成片画面做场景检测，每个切点离最近的拍（`--half` 时半拍）不超过 3 帧算合格。脚本会打印检测到几个硬切，和分镜对不上就用 `--cuts` 直接给时刻。检查图里黑线是网格、绿线是合格切点、红线是超差切点。

**probe**：`probe.sh <片> --size 1920x1080 --color bt709 [--lufs -14]`，`export_1080p.sh` 结束时自动跑。除分辨率外还查：CFR（r_frame_rate 与 avg_frame_rate 一致）、音画时长差不超过 1 帧、全片解码零错误（`--quick` 跳过）、真峰值不超过 -1.2 dBTP、色彩标签三项都是 bt709、响度偏离目标不超过 1 LU。

**可读性**：联系表每格就是 480 宽，格子里的字幕和关键字读不清，手机上也读不清，按逐秒清单的文字项记问题。

**丰富度**：数联系表上画面状态的变化（切镜、换图卡、大元素进出、推拉到新构图都算一次）。参考片拆解给出的及格线：5 分钟左右的知识短片每分钟 12 次以上，长教程每分钟 9 次以上。低于及格线，在问题表里写出最长的几段静止区间和打算加什么。

## 交付前核对

- 上面几道门的输出都贴进交付说明，probe 为 PASS，时长与分镜总时长相差不超过一帧。
- 没有音轨就在交付说明里写无音轨。
- 配乐是程序合成的占位曲时，交付说明里写可替换。
